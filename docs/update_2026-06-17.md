# RoboDataset Studio V3 Update Notes - 2026-06-17

## What Changed Today

### Config Library

- Added independent config management inside the existing Config Library workflow.
- Added `New`, `Copy`, `Rename`, and `Delete` actions without creating another management page.
- Kept config creation as one continuous flow: edit form/YAML, save, duplicate, rename, delete, or load into project from the same screen.
- `New` creates a blank unsaved config draft. It is only written to the config library after `Save`.
- `Copy` saves a copy of the currently open config using an automatic `_copy` suffix, preserving the current editor/form content.
- `Save` writes the current form/YAML to the config name shown in `Config name`; if that name does not exist, it creates a new config.
- Added editable selection fields for common values while keeping manual input:
  - Environment type
  - Lighting
  - Robot name
  - Robot model
  - Language
  - Task family
  - Success condition
  - Upload profile
- ROS graph now adds detected robot namespaces from `JointState` topics into Robot name/model choices.
- Long ROS topic names in topic trees now show fully with tooltips and horizontal scrolling.
- Global `Refresh Graph` moved to the top-right menu area and styled as a visible action button.
- The `Inspector` menu action now toggles the inspector dock open/closed.
- `Tools -> ROS Discovery` was removed because ROS topic selection now lives in `Config Library -> ROS Topics`.
- `Config -> New Config` was removed because new config creation is handled directly inside `Config Library`.

### Collection Workflow

- Collection page now polls backend recording tasks after `Start Recording`.
- Start/stop recording displays:
  - active task id
  - session output directory
  - task status
  - final result or failure
- Stop recording now keeps polling until the recorder reports `done`, `failed`, or `cancelled`.
- Preflight now checks configured ROS topics using topic info and echo-once instead of only counting configured streams.
- Review and conversion pages now default to the current project paths so fewer paths need manual entry.

### Review Workflow

- Session scan now supports passing a `raw_sessions` folder; the backend automatically resolves the latest `session_*` folder.
- Scan results populate an episode table with:
  - episode name
  - persisted manual mark
  - status
  - issues
  - path
- Added manual episode marks:
  - `Mark Keep`
  - `Mark Warning`
  - `Mark Reject`
  - `Clear Mark`
- Marks are persisted in:

```text
<session>/review/review_marks.yaml
```

- Reopening the app and scanning/checking the same session reloads the previous marks.

### Convert Workflow

- Session scan now populates a selectable session table.
- Merge and HDF5 conversion use checked sessions first, falling back to the manual comma-separated session field.
- Merge and HDF5 conversion now run as backend tasks instead of blocking the UI while the command is running.
- Convert page polls task status and shows the final task result.

### Upload Workflow

- Upload page now supports SSH port.
- Upload, repair/resume, and remote verify now run as backend tasks instead of blocking the UI.
- Upload page polls task status and shows the final result.
- Upload defaults are loaded from the current project config when available:
  - local path defaults to `<project>/exports`
  - remote path/host/username/port default from `project_config.yaml -> upload`
- Upload page now supports:
  - file or folder local source selection
  - local manifest preview
  - local manifest verification
  - remote directory listing
  - remote parent navigation
  - selecting the current remote directory as the upload target
  - creating a remote folder
  - remote space check

## Current Usage Flow

### 1. Create Or Load Config

1. Click `Config -> Config Library`.
2. Click top-right `Refresh Graph` if ROS is running.
3. Enter a config name.
4. Fill the config tabs:
   - Environment
   - Robot
   - Instruction
   - Recording / Image
   - ROS Topics
   - Upload
   - AI Match Config
5. In `ROS Topics`, expand topic groups and select the needed topics.
6. Click `Refresh config from selected topics`.
7. Click `Apply form -> YAML` if you changed form fields.
8. Click `Validate`.
9. Click `Save`.

Optional management actions:

- `New`: start a blank config draft, then enter a name and click `Save`.
- `Copy`: copy the currently open config to a new config with a `_copy` suffix.
- `Rename`: rename the selected config to the value in `Config name`.
- `Delete`: remove the selected config. `default_calvin` is protected.
- `Load into current project`: bind the selected config to the open project.

### 2. Record A Session

1. Open or create a project and bind a config.
2. Go to `Tools -> Collect`.
3. Click `Refresh Listener Plan`.
4. Choose stop mode:
   - Manual: start and stop manually.
   - Duration: record for a fixed number of seconds.
   - Sample count: record until the target sample count.
5. Click `Check Nodes`.
6. Open `Inspector` if you want to monitor topic echo, hz, or image preview.
7. Click `Start Recording`.
8. Watch `Task` and `Session` labels.
9. For manual mode, click `Stop Recording` when finished.
10. Wait until the task status becomes `done` or `failed`.

Recorded data is written under:

```text
<project>/raw_sessions/session_YYYYMMDD_HHMMSS/
  dataset_config.yaml
  collection_config.yaml
  training/
    episode_*.npz
    lang_annotations/auto_lang_ann.npy
```

### 3. Review A Session

1. Go to `Tools -> Data Review`.
2. The session field defaults to `<project>/raw_sessions`.
3. Click `Scan Session`.
4. If a raw sessions root was provided, the latest `session_*` is selected automatically.
5. Click `Check Session`.
6. Review episode status and issues in the table.
7. Select an episode row and click:
   - `Mark Keep`
   - `Mark Warning`
   - `Mark Reject`
   - `Clear Mark`
8. Marks are saved and will reload next time.

### 4. Convert Sessions

1. Go to `Tools -> Convert`.
2. The raw sessions root defaults to `<project>/raw_sessions`.
3. The output directory defaults to `<project>/exports`.
4. Click `Scan Sessions`.
5. Check the sessions you want to use.
6. Click `Merge Sessions` to create a merged CALVIN-style output.
7. Click `Convert To HDF5` to generate:

```text
<output_dir>/calvin.hdf5
```

8. Wait until the convert task reaches `done`.

### 5. Upload / Repair / Verify

1. Go to `Tools -> Upload`.
2. Confirm:
   - Local file/folder
   - Remote path
   - Host
   - Port
   - Username
3. Click `Check Dependencies`.
4. Click `Build Manifest` to preview which local files will be uploaded.
5. Click `Verify Local Manifest` to check the generated local manifest.
6. Click `List Remote` to list the current remote directory.
7. Double-click a remote directory row to enter it, or click `Up` to go to the parent directory.
8. Use `Create Remote Folder` if a new remote folder is needed.
9. Click `Use Current Remote` when the remote path field is the intended upload target.
10. Click `Check Remote Space` before uploading a large dataset.
11. Click `Upload` for normal transfer.
12. Click `Repair / Resume` to verify remote files and resend missing/hash-mismatched files.
13. Click `Verify` to check the remote files against the local manifest.
14. Wait until the upload task reaches `done` or `failed`.

Server requirements:

- SSH server reachable from the workstation.
- `ssh` available locally.
- `rsync` available locally for upload and repair/resume.
- `python3` available remotely for manifest verification.
